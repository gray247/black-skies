# Historical Planning Policy

## Purpose

This policy defines how older planning, governance, salvage, rebuild,
and audit documents should be read now.

Historical planning documents remain important evidence.
They are not current product authority unless an active canonical
product-system document explicitly carries a surviving decision forward.

## Core Policy

- historical planning documents remain evidence
- older documents are not current product authority by default
- older runtime-governance authority remains limited to its historical
  lane
- repository salvage, product recovery, and future rebuild are distinct
- mixed documents must remain intact
- surviving truth should be extracted into current authoritative
  artifacts before later archival movement
- heavily referenced documents should receive status notices before
  relocation
- file movement, link repair, and broad archive migration require a
  separate maintenance pass
- current product authority is defined through the active
  product-system spine

## Terminology

`Repository salvage`

- preservation of useful code, tests, documents, and evidence from the
  existing repository

`Product recovery`

- the current discovery, reconciliation, and roadmap-reconstruction work

`Future rebuild`

- a later implementation decision concerning reuse, replacement,
  rewriting, and new construction

The branch name `salvage/minimal-two-surface-shell` describes repository
lineage.
It is not the current product-development stage and it does not
authorize implementation.

## Handling Rules

- Do not move, rename, delete, or rewrite historical planning files in
  ordinary discovery passes.
- Preserve mixed documents intact after surviving truth is extracted into
  active authority artifacts.
- Treat old runtime-governance plans, salvage plans, rebuild plans, and
  roadmap ledgers as historical evidence unless a current canonical
  product-system document explicitly cites a surviving decision.
- Before relocating a heavily referenced historical file, add a short
  status notice that explains what it still provides and what it no
  longer authorizes.

## Not In Scope Here

This policy does not perform:

- archival movement
- broad link repair
- historical cleanup across the full repo
- truth extraction from every older document
- implementation planning
