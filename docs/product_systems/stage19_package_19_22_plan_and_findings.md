The accepted V1 product claim is limited to the two-window Windows writing
foundation, local project and manuscript-unit management, bounded editing,
durable Save/reopen/recovery, deterministic Markdown export, optional
explicitly approved advisory critique, and offline core operation.

Package `19.22` does not authorize a tag, public release, signing request,
publication, announcement, connector, provider qualification, V2/V3 feature,
or production-readiness claim.

## 2. Candidate invalidation rule

The accepted Package `19.20` installer remains historical qualification
evidence until Package `19.22` completes its candidate-impact review.

Changes to runtime source, manifests, lockfiles, dependency patches, resources,
version data, Electron Builder configuration, production-build scripts, or
packaging-verifier scripts invalidate the prior candidate for current closure
purposes and require rebuild plus affected qualification.

Documentation, tests, findings records, and CI-only changes do not invalidate
the binary unless artifact inspection shows that they enter the package.

## 3. Closed-loop protocol

Every finding follows:

```text
discover -> ledger -> reproduce -> root cause -> regression witness
-> minimal repair -> focused rerun -> subsystem rerun -> invalidated gates
-> clean full matrix -> exact-commit CI -> closure or reopen
```

No warning ceiling, suppression, new skip, timeout increase, retry increase,
or weakened assertion may substitute for repair.
