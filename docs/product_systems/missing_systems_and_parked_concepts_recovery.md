## 4. Recovered Editorial Workflow

The broader editorial experience was fragmented when old `Critique` was split.
That split was still the correct move.
It removed the false assumption that one system should own evaluation, note persistence, unresolved attention, continuity review, rewrite application, rubric logic, and conversational explanation at the same time.

The loss was not architectural clarity.
The loss was journey clarity.

What is currently preserved well:

- `Critique / Evaluation` owns findings and evaluation posture.
- `Feedback Notes / Revision Resolution` owns durable notes.
- `Signal Architecture` owns durable attention state.
- `Continuity` owns continuity-specific advisory review.
- `Draft Generation / Rewrite Loop` owns rewrite-generation questions.
- `Companion` owns explanation and routing support.

What is currently missing:

- an explicit editorial workflow view showing how those systems cooperate,
- a shared “from finding to action to closure” path,
- a clear explanation of when an issue should become a note, signal, continuity item, rewrite prompt, or dismissed observation,
- a user-facing articulation of the editorial whole after decomposition.

Conclusion:

The editorial workflow should be recovered as a cross-system capability lane.
It should not collapse back into one monolithic `Critique` dossier.

## 5. Recovered Story-Foundation Workflow

`Author Intent / Story Setup` is not adequately resolved by being merely parked in `Workflow Spine / Author Journey`.

The parking decision was useful because it prevented a premature startup gate.
It did not answer whether story foundation is:

- a light profile,
- an evolving design notebook,
- a structured optional setup path,
- or a small truth-owning system for project goals and boundaries.

The current treatment is strong enough to preserve doctrine:

- it must not gate direct writing,
- it must not silently become truth,
- and it can hold provisional accepted project truth only under explicit author action.

The current treatment is not strong enough to close discovery.

Conclusion:

`Author Intent / Story Setup` deserves separate treatment at discovery level.
That does not mean it must become a separate implementation surface.
It does mean the idea is too central and too repeatedly referenced to stay a vague parked note indefinitely.

## 6. Validation-Program Distinction

Not every missing idea should become a product-system dossier.

The repository already distinguishes some future work correctly as validation rather than product:

- local-model validation,
- paid-API validation,
- routing validation,
- long-form memory transfer validation,
- trilogy and series continuity transfer validation,
- genre stress testing,
- other AI and evidence-quality studies.

These belong to future validation programs unless and until Black Skies decides to expose a user-facing surface derived from them.

Current distinction:

- current discovery candidates: `Author Intent / Story Setup`, `Ideation / Premise Discovery / Brainstorming`, and possibly later branching support.
- explicitly excluded or parked concepts: `Voice Notes / Dictation / Transcription`, research workflow, and standalone UI identity promotion.
- internal validation programs: narrative stress testing, model benchmarking, local-versus-API evaluation, and originality or similarity studies for now.
