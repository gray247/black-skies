# Phase 30 Workflow Philosophy

Status: Draft
Date: 2026-05-22
Phase: 30 - GUI / Workflow Realignment Spec
Pass: 1A - Workflow Philosophy Codification

## Purpose

This document codifies the workflow philosophy emerging from Phase 30 exploration.
It is governance guidance, not implementation guidance.
It does not define layouts, runtime features, or speculative AI capability.

## Core Workflow Philosophy

Black Skies should behave like a writing-first system with summonable structural intelligence, not a permanent telemetry cockpit.
The product should help writers discover narrative structure, fragility, imbalance, pressure, escalation, and hidden patterns without turning interpretation into grading.

## Cognitive Hierarchy

- the words come first
- immediate authoring context comes second
- contextual support comes third
- structural analysis comes after authoring needs are stable
- support, recovery, diagnostics, and experimentation are bounded exception classes

Nothing should outrank the writer's current sentence-level or paragraph-level focus without strong justification.

## Visibility Hierarchy

- primary: the Writing Surface and the minimum set of controls required to sustain drafting continuity
- contextual: state-sensitive aids that appear in support of the current task
- summonable: intelligence, structure, and support tools that remain available without remaining ambient
- advanced: low-frequency, high-complexity, or high-risk systems
- hidden: diagnostics, dev/test seams, and background automation that do not need ordinary user attention

## Contextual vs Persistent UI Rules

- persistent visibility must be earned by workflow centrality
- contextual visibility is preferred for most intelligence, status, and structural surfaces
- persistent presence is not justified merely because a system is useful sometimes
- repeated usefulness does not automatically justify permanent occupation of the primary writing field

## Nothing Competes With The Words

The Writing Surface is sovereign.
No adjacent system should create a competing center of gravity while the user is actively drafting.
Even important support or structural systems must remain subordinate to active prose attention.

## Progressive Disclosure Philosophy

Power should be available without being omnipresent.
The workflow should reveal capability as the user's task changes rather than asking the user to mentally filter a full control plane at all times.

Rules:

- advanced tools should be reachable, not ambient
- interpretation tools should be summonable before they are persistent
- support/recovery tools should surface when needed, not live as default clutter

## Workflow Calmness Principles

- fewer simultaneous authority claims are better than more
- lower noise is better than permanent instrumentation
- contextual reveal is better than fixed dashboard density
- structural insight should reduce confusion, not create a second workload

## Anti-Dashboard Principles

- the interface must not become a permanent wall of gauges, scores, and state badges
- secondary instrumentation should not masquerade as authoring progress
- "more panels" is not a sign of deeper workflow maturity
- no persistent telemetry wall should define the product's daily rhythm

## Hover / Pin Governance Philosophy

- hover is appropriate for light discovery, preview, and low-risk contextual reveal
- pinning is appropriate when the user intentionally promotes a contextual surface into temporary working relevance
- pinning does not automatically grant permanent authority or permanent placement
- pinned state should remain reversible and should not behave like a backdoor to uncontrolled clutter

## Companion Governance Philosophy

The companion is not an omniscient narrative authority.
It is a bounded interpretive assistant.

Rules:

- companion guidance is assistive, not judicial
- companion presence should be local-first where possible and legible when not
- companion visibility must not turn the Writing Surface into a chat-first workflow
- companion status, routing, or telemetry should not dominate author attention

## Interpretive Instruments Philosophy

Narrative instrumentation is useful when it helps reveal structure, tension, pacing, fragility, imbalance, repetition, or escalation.
It becomes harmful when it pretends to assign final quality.

Rules:

- use instruments that help inspection and interpretation
- reject scoring systems that collapse interpretation into grades
- no "story score" or similar fake-certainty summary systems

## Structural vs Contextual Separation

- structural systems help the writer reason about organization, relationships, sequence, and placement
- contextual systems help the writer with the current local task
- structural visibility should not crowd local drafting attention unless the user intentionally shifts modes
- contextual systems should not impersonate structural authority

## Dual-Monitor Philosophy

Dual-monitor workflow is a strong candidate direction, but not irreversible product law yet.
Any second-monitor concept must preserve primary-screen Writing Surface sovereignty.

Rules:

- monitor two is not an overflow dump
- monitor two is not a permanent telemetry wall
- monitor one remains visually dominant for authoring
- second-screen content must still obey authority layering and progressive disclosure

## Workflow-State Sensitivity

Visibility and interaction should respond to workflow state.
Different stages justify different surfaces:

- focused drafting
- structure review
- capture and reorganization
- support/recovery intervention
- advanced analysis

The system should show what is relevant to the current state, not everything that exists.
