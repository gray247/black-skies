# Phase 30 Workflow Ownership Matrix

Status: Draft
Date: 2026-05-22
Phase: 30 - GUI / Workflow Realignment Spec
Pass: 2 - Workflow Policy and Story Unit Governance

## Purpose

This matrix defines which authority layer owns which workflow categories.
It governs authority, attention, and mutation boundaries without defining exact layout or implementation.

## Writing Surface Ownership

- primary authority owner: Writing Surface
- allowed secondary systems: contextual status, bounded contextual intelligence, limited structure cues
- forbidden authority escalation: support/recovery, diagnostics, experimental shells, or dense intelligence taking primary authoring focus
- contextual allowance rules: contextual systems may appear only in support of the current authoring moment
- mutation-risk rules: direct prose mutation and deliberate generation entry may live here; intelligence-assisted mutation remains tightly constrained
- validate-first rules: critique/rewrite authority does not become normal writing flow by default
- user-attention expectations: calm, focused, low-overload, authoring-first

## Contextual Workflow Ownership

- primary authority owner: contextual systems subordinate to Writing Surface
- allowed secondary systems: Command Center candidate, bounded status, support signals when relevant
- forbidden authority escalation: contextual surfaces becoming a second primary workspace by default
- contextual allowance rules: activate only when state, timing, or local relevance justifies it
- mutation-risk rules: contextual surfaces should avoid high-consequence mutation authority
- validate-first rules: intelligence surfaces stay contextual unless stronger proof exists
- user-attention expectations: assistive, limited, suppressible

## Command Center Candidate Ownership

- primary authority owner: Command Center candidate
- allowed secondary systems: contextual intelligence, structure/navigation, model/cost status, bounded support context
- forbidden authority escalation: becoming the default mutation hub or displacing Writing Surface primacy
- contextual allowance rules: may hold denser structure and analysis than the Writing Surface
- mutation-risk rules: primary mutation ownership is not approved here in Pass 2
- validate-first rules: command-like mutation pathways and intelligence-assisted mutation remain unresolved
- user-attention expectations: analysis-first, structure-first, not chaotic

## Support / Recovery Ownership

- primary authority owner: support and recovery systems
- allowed secondary systems: Writing Surface context, contextual notifications, bounded Command Center support state
- forbidden authority escalation: support workflows becoming ambient authoring tools
- contextual allowance rules: visible when needed, reduced when not needed
- mutation-risk rules: restore/retry/recovery actions stay clearly exceptional and consequential
- validate-first rules: mixed diagnostics/support seams remain unresolved
- user-attention expectations: honest, explicit, non-routine

## Diagnostics / Dev Ownership

- primary authority owner: diagnostics/dev systems
- allowed secondary systems: none by default outside explicit support policy
- forbidden authority escalation: test or diagnostic seams inheriting product-facing authority
- contextual allowance rules: only through explicit later approval
- mutation-risk rules: any hidden or injected state control remains out of normal workflow governance
- validate-first rules: diagnostics bridge promotion remains unresolved
- user-attention expectations: hidden, gated, or explicitly non-product

## Background Automation Ownership

- primary authority owner: background automation candidates
- allowed secondary systems: status summaries, internal orchestration, low-visibility helpers
- forbidden authority escalation: visible authority without separate governance approval
- contextual allowance rules: surfaced only when necessary for trust or clarity
- mutation-risk rules: no silent user-facing mutation authority
- validate-first rules: routing metadata and hidden orchestration remain bounded
- user-attention expectations: minimal, low-pressure, largely invisible

## Intelligence Workflow Ownership

- primary authority owner: contextual systems or Command Center candidate depending on task
- allowed secondary systems: Writing Surface-adjacent contextual cues, support status when relevant
- forbidden authority escalation: intelligence becoming unquestioned primary authoring authority
- contextual allowance rules: descriptive and advisory intelligence remain below prescriptive authority
- mutation-risk rules: intelligence-assisted mutation is a distinct high-risk class
- validate-first rules: rewrite/apply remains validate-first
- user-attention expectations: bounded, legible, non-theatrical

## Mutation Workflow Ownership

- primary authority owner: Writing Surface for ordinary authoring mutation; support/recovery for exception mutation
- allowed secondary systems: tightly constrained contextual review or Command Center candidate review contexts
- forbidden authority escalation: dense analysis surfaces or experimental systems owning mutation by default
- contextual allowance rules: contextual support may lead into mutation review, but not silently execute it
- mutation-risk rules: interpretation plus mutation requires the strongest governance
- validate-first rules: intelligence-assisted mutation, merge/split authority, and diagnostics-linked mutation remain unresolved
- user-attention expectations: explicit, deliberate, high-trust, consequence-aware
