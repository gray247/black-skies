## Product Spine

Black Skies is not primarily a proof-boundary project. Its product spine is a writing-first, structure-aware, continuity-sensitive narrative studio.

The accepted spine is:

- Writing Surface sovereignty
- Story Units as the emerging narrative primitive
- Command Center as subordinate analysis / navigation / structure support
- Contextual Intelligence as bounded and advisory
- Companion as interpretive, not authoritative
- Continuity as the base layer for safe reload / reopen / project-switch behavior
- Narrative topology as directional structure visibility, not graph theater
- Hybrid Narrative Memory as a real product direction, currently split into Memory Lab and Black Skies-adjacent planning

## Roadmap Alignment Assessment

The current roadmap is technically valid, but strategically incomplete.

What it gets right:

- It preserves Writing Surface primacy.
- It keeps Command Center subordinate.
- It treats Story Units as conceptual/workflow-governed rather than over-promoting them into premature canonical persistence.
- It preserves the proof-boundary lanes and closes them with caveats.

Where it is incomplete:

- The execution spine still reads like infrastructure and governance first, product spine second.
- `RDM-CONTINUITY-001` is not just plumbing; the evidence describes it as base-layer support for Story Units, command surfaces, and continuity-sensitive work.
- The current Phase 32-40 framing is still too GUI- and infrastructure-weighted relative to the product direction already accepted in Phase 20, Phase 21, Phase 30, and Memory Lab.

## Hybrid Narrative Memory Recommendation

Yes. Hybrid Narrative Memory should become a named Black Skies workstream.

Recommendation:

- Keep Memory Lab as the experimental / proving-ground program.
- Add a named Black Skies workstream for Hybrid Narrative Memory so it is not treated as a sidecar concept.
- Treat the workstream as dependent on Story Units, continuity, narrative cognition, and bounded intelligence policy.

Dependencies:

- Story Units
- Continuity
- Narrative Intelligence
- Narrative Topology

Systems that would consume it:

- Companion
- Command Center analysis surfaces
- future narrative tooling
- future memory / continuity arcs

## Candidate Phase 32 Recommendation

Candidate Phase 32 should be promoted sooner, but not as generic multi-monitor hardening alone.

The better bridge is:

- Story Unit Data Model + Qualitative Evaluation Foundation

Why:

- Phase 30 governance already says Story Units are accepted conceptually but not yet canonical persisted runtime structure.
- The unresolved questions around Story Unit persistence, lifecycle, and evaluation are exactly the kind of pre-GUI-overhaul gap that should be resolved before broader layout work becomes the main lane again.
- Multi-monitor / cross-window work is useful, but it should not outrun the product primitive it is meant to expose.

Recommendation:

- Pull the Story Unit / qualitative-evaluation bridge forward ahead of or alongside the current Phase 32 multi-monitor framing.
- If numbering cannot change immediately, treat the Story Unit foundation as the first sub-arc that must be resolved before the multi-monitor expression becomes primary.
