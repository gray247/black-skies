## Matrix Method

This is question mapping, not answer finalization.

For each provisional family, this pass asks what must be decided across:
- authority type
- visibility
- mutation
- inspection
- advisory
- recovery
- diagnostics
- vocabulary
- command/search inheritance
- status/truth exposure
- output/export
- support/dev boundary
- normalization pressure
- legitimacy drift
- implementation waste risk

The matrix does not canonize workflow states, convert provisional families into product navigation, or authorize implementation. It preserves the distinction between state, constraint, overlay, and authority class.

## Executive Findings

- The highest-risk unanswered questions concern mutation authority, command/search inheritance, support/recovery exception boundaries, and diagnostics audience separation.
- Focused Drafting blocks canon until its dual role as state and constraint is reconciled.
- Generation, Rewrite / Apply, and Mutation-Boundary Authority cannot be collapsed without losing blast-radius governance.
- Support / Recovery Exception, Recovery Diagnostics, and Diagnostics / Developer-Test require separate authority answers before any ordinary workflow state can safely include support or diagnostics surfaces.
- Structure / Organization cannot stabilize until Story Unit pressure is reconstructed.
- Export / Output should remain an authority class until future states explain when output implies completion, maturity, or workflow closure.
