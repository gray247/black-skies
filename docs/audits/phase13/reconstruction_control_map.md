# Reconstruction Control Map

## 1. Scope Declaration

This artifact is planning/control-map only.

This artifact does not authorize implementation.

Blocked domains remain blocked unless separately reauthorized.

Implementation candidates are not implementation approval.

The map is organizational and procedural, not architectural canon.

## 2. Reconstruction Control Map Purpose

Arc B existed because governance containment had to be made explicit before further reconstruction planning could stay coherent.

Governance containment was required because visibility, diagnostics, outputs, artifacts, validation, maintenance framing, and partial planning language were repeatedly capable of borrowing unauthorized authority.

Reconstruction sequencing now matters because unresolved source-of-truth, recovery, retrieval, lifecycle, and validation questions can distort later planning if they are allowed to inherit certainty by adjacency.

Planning must remain controlled because implementation hunger can overread governance completion as permission.

Implementation hunger remains dangerous because it can convert pressure analysis, candidate language, maintenance evidence, or clean validation into roadmap gravity.

The governance work from Arc B must now compress into operational planning so future work can be ordered without reopening blocked domains.

## 14. Human/Orchestrator Authority

Explicit human/orchestrator review is required for:

- any implementation candidate classification
- any blocked-domain reconsideration
- any work with unresolved source-of-truth, diagnostics, export/output, lifecycle, or validation authority impact
- any scope expansion beyond maintenance-safe work
- any claim that validation or control-map status supports implementation eligibility

The following may proceed as maintenance-only:

- bounded maintenance inside the Pass 44 safe-maintenance lane with evidence
- narrow docs-only governance updates
- constrained tests/build/dependency maintenance with authority-impact review

The following must remain blocked:

- all hard-blocked domains
- any attempt to turn candidate language into approved work
- any hidden reauthorization by wording, visibility, repetition, or planning placement

Escalation conditions:

- ambiguous authority impact
- unresolved dependency interpretation
- validation evidence quoted beyond scope
- discovered issue that requires implementation
- scope drift into blocked domains

## 15. Operational Procedure Summary

Operational guidance:

- allow: governance-only work or maintenance work that stays within safe-maintenance rules and evidence requirements
- block: hard-blocked domains, unsupported no-impact claims, hidden reauthorization, or scope drift
- escalate: ambiguous authority cases, implementation-candidate pressure, blocked-domain adjacency, or unresolved dependency interpretation
- maintenance with evidence: permitted only with named files, authority-impact review, blocked-areas-not-touched, discovered-but-not-fixed, and scoped validation evidence
- implementation candidate only: planning classification only; not permission
- explicit authorization required: any implementation work
